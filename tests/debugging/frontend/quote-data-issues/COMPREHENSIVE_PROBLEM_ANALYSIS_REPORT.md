**問題來源**: 用戶實際測試發現的數據錯誤

## 🚨 **核心問題總覽**

基於用戶提供的5張截圖證據，發現以下三個關鍵數據邏輯錯誤：

### **問題1: 報價單號格式不正確** 
- **現象**: 顯示 `QT-019`
- **期望**: 根據系統規範應為 `QT2025000019` 格式
- **嚴重程度**: 🔴 高 - 影響業務流程標準化

### **問題2: 產品名稱顯示錯誤**
- **現象**: 顯示 `Unknown Product`  
- **期望**: 應顯示實際產品名稱 (如: "測試商品 A")
- **嚴重程度**: 🔴 高 - 核心業務數據錯誤

### **問題3: 狀態寫入錯誤**
- **現象**: 用戶選擇"已發送"但資料庫顯示"Draft"
- **期望**: 用戶選擇的狀態應正確寫入資料庫
- **嚴重程度**: 🔴 高 - 業務流程管理失效

## 🔍 **根因分析** 

### **問題1根因: 前端顯示邏輯錯誤**
- **位置**: Quote詳細頁面的顯示邏輯
- **分析**: 資料庫中`quote_number`格式正確(`QT2025000019`)，但前端顯示為`QT-019`
- **推測**: 前端可能使用了錯誤的格式化邏輯或讀取了錯誤的欄位

### **問題2根因: 產品名稱關聯查詢失效**
- **位置**: Quote -> QuoteItems -> Products 的關聯查詢
- **分析**: 資料庫中有正確的product_id(832)和對應的產品名稱("測試商品 A")
- **推測**: 前端或API層未正確執行 JOIN 查詢獲取產品資訊

### **問題3根因: 表單提交狀態處理錯誤**
- **位置**: QuoteController store方法或Go API處理邏輯
- **分析**: 用戶選擇"已發送"但資料庫寫入"draft"
- **推測**: 表單欄位名稱不匹配或狀態值轉換邏輯錯誤
