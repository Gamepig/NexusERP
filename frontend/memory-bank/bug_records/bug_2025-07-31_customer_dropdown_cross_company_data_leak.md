# Bug 記錄 - 客戶下拉選單跨公司資料洩漏

## 📅 基本資訊
- **發現日期**：2025-07-31
- **任務 ID**：2b (修復客戶管理 - 客戶下拉選單跨公司資料洩漏問題)
- **嚴重程度**：高 (嚴重安全問題 - 多租戶資料隔離失效)
- **狀態**：已解決
- **影響範圍**：所有使用客戶下拉選單的功能，特別是銷售訂單建立頁面

## 🐛 問題描述
用戶在建立銷售訂單時，客戶下拉選單顯示了其他公司的客戶資料：
- **安全問題**：多租戶資料隔離機制失效
- **表現症狀**：下拉選單中出現如 "user0001_4972 的公司 客戶 2" 等其他公司的客戶
- **影響範圍**：所有需要選擇客戶的功能頁面

## 🔄 重現步驟
1. 用戶登入系統（如 test@example.com）
2. 進入銷售訂單建立頁面：`http://127.0.0.1:8000/customers/1/orders/create`
3. 點擊客戶下拉選單
4. 觀察到下拉選單顯示了其他公司的客戶資料

## 🔍 根本原因分析

### 技術分析
1. **控制器問題**：
   - 位置：`app/Http/Controllers/API/CustomerController.php:26-28`
   - 問題代碼：
     ```php
     // 只顯示屬於當前用戶的客戶
     // 暫時註釋以便測試 - 在生產環境應啟用多租戶篩選
     // $query->where('created_by_user_id', auth()->id());
     ```

2. **多租戶篩選機制被停用**：
   - 註釋說明：「暫時註釋以便測試」
   - 影響：所有公司的客戶資料都會被返回到前端
   - 安全風險：違反多租戶資料隔離原則

3. **篩選邏輯錯誤**：
   - 原始邏輯：使用 `created_by_user_id` 篩選
   - 正確邏輯：應使用 `company_id` 篩選
   - Customer 模型有 `company_id` 欄位，但未被正確使用

### 架構分析
- **多租戶模式**：系統採用 `company_id` 作為租戶隔離標識
- **會話管理**：`current_company_id` 儲存在用戶會話中
- **資料模型**：Customer 模型包含 `company_id` 欄位用於多租戶隔離

## 🛠️ 解決方法

### 修復策略
重新啟用並正確實作多租戶篩選機制，使用 `company_id` 而非 `created_by_user_id`

### 修復代碼

**修復前 (`app/Http/Controllers/API/CustomerController.php:26-28`)：**
```php
// 只顯示屬於當前用戶的客戶
// 暫時註釋以便測試 - 在生產環境應啟用多租戶篩選
// $query->where('created_by_user_id', auth()->id());
```

**修復後：**
```php
// 只顯示屬於當前公司的客戶 - 多租戶篩選
$companyId = session('current_company_id') ?? session('app.current_company_id');
if ($companyId) {
    $query->where('company_id', $companyId);
}
```

### 修復要點
1. **啟用多租戶篩選**：移除註釋，重新啟用篩選機制
2. **使用正確的篩選條件**：從 `created_by_user_id` 改為 `company_id`
3. **會話變量處理**：支援兩種會話變量格式的回退機制
4. **安全性優先**：確保只返回當前公司的客戶資料

## 🚫 預防措施
