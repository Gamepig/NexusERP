# Task ID: 12
# Title: Phase 1: OCR Integration for Purchase Invoices
# Status: done
# Dependencies: 11
# Priority: medium
# Description: Integrate an external OCR service to automate data entry from scanned or uploaded supplier invoices, as detailed in PRD 4.2.
# Details:
Create a file upload endpoint that accepts invoice images/PDFs. This endpoint sends the file to an external OCR API. Parse the structured JSON response from the OCR service to pre-fill a new supplier invoice form in the UI. Implement a validation step for the user.

# Test Strategy:
Mock the OCR API to test the data mapping logic. Use a set of sample invoices (different layouts, languages) to test the end-to-end flow and measure the accuracy of data extraction.

## 3. 資料解析與驗證 (Data Parsing and Validation) [done]
### Dependencies: 12.2
### Description: 將 OCR 服務的結構化 JSON 回應解析為標準化的內部發票資料模型，並實作驗證規則。
### Details:
定義一個內部 InvoiceData 模型 (例如 invoiceNumber, totalAmount, issueDate, vendorName, lineItems)。編寫一個解析器，從 OCR JSON 回應中提取相關欄位並映射到此模型。實作伺服器端驗證以確保提取資料的正確性 (例如 totalAmount 為數字，issueDate 為有效日期)。
<info added on 2025-07-19T10:59:39.619Z>
此實作將包含一個專用的 `InvoiceDataParser` 服務，負責將 `OCRResponse.StructuredData` 解析並映射到標準化的內部 `InvoiceData` 模型。驗證將透過建立一個包含欄位特定驗證器 (例如日期、金額、格式驗證) 的驗證管線來實現，並使用 `ValidationResult` 結構來追蹤錯誤和警告。需支援錯誤處理和部分資料解析，並包含資料映射和正規化函數。此服務將與現有的 OCR 和發票服務進行整合。將編寫全面的測試以涵蓋各種發票版面。

### Dependencies: 12.1, 12.2, 12.3, 12.4
### Description: 實作 OCR 失敗時的穩健錯誤處理機制，包括使用者回饋和備用方案。
### Details:
