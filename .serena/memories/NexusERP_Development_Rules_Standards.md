# NexusERP 開發規範與標準

## 1. 檔案與文件規範

### 檔案組織
- **文件位置**: 所有說明文件、規劃文件、需求文檔統一放在 `documents/` 資料夾
- **環境配置**: 所有環境變數集中於根目錄 `.env`
- **技術名詞**: 一律使用台灣用語，參考 `documents/CS_TW_CN_TERMS.md` 和 `CS_TW_CN_TERMS_2.md`

### 必讀技術規範文件
- `documents/claude_code_rules.md` - 核心開發規範（本規則的詳細版本）
- `documents/frontend_file_structure_spec.md` - 前端架構規範
- `documents/backend_file_structure_spec.md` - 後端架構規範
- `documents/database_spec.md` - 資料庫設計規範

## 2. 程式碼品質標準

### 效能優先原則
- **效能優先、簡潔為王、最小代碼量**
- 嚴格遵守命名規則與縮排
- **優先使用 stored procedure** 減輕程式運作負擔，特別是大量資料庫運算
- 絕對避免巢狀迴圈
- 禁止過深的 if/else，複雜邏輯應拆分為小函數

### 註解規範
- 關鍵業務邏輯必須有詳細中文註解，解釋「為什麼」
- 複雜算法需註明時間/空間複雜度
- API 需完整標註參數與回傳值說明
- 每個 class、function 必須有 docstring (Python) 或 JSDoc (JS/TS)

### 語言與國際化
- 所有文件、註解、訊息一律使用正體中文或英文
- **嚴禁使用中國用詞**
- 支援多語系 (i18n) 機制

## 3. 強制性任務前準備工作

### 必要準備步驟
每個子任務開始前必須完成：

1. **任務理解與需求分析**
   - 使用 `task-master show <task-id>` 詳細了解任務需求
   - 分析 Implementation Details 和 Test Strategy
   - 確認依賴關係和複雜度

2. **專案架構與規範研讀**
   - 必讀上述所有技術規範文件
   - 理解任務相關的技術規格

3. **現有程式碼結構分析**
   - 分析相關專案結構和路由配置
   - 檢查依賴關係和中介軟體機制

4. **知識庫與最佳實踐研究**
   - 搜尋 `memory-bank/` 目錄中的相關經驗
   - 查找類似任務的已知問題和解決方案

5. **實作策略制定**
   - 確定技術方案和相容性評估
   - 識別潛在風險和測試策略

## 4. 測試與品質保證

### 測試規範
- **測試檔案**: 放在 `Tests/` 目錄，命名規則 `test_*.py`
- **覆蓋率**: 單元測試覆蓋率需達 **80% 以上**
- **Mock 策略**: 只 mock 外部依賴，不 mock 內部邏輯
- **測試範圍**: 涵蓋成功、失敗、邊界情況

### Playwright MCP 強制測試
- **所有完成功能都必須使用 Playwright MCP 進行實際測試**
- 測試核心使用者流程、UI/UX 變更、API 整合
- 測試失敗必須立即修復，不得標記為完成

## 5. UI/UX 與前端規範

### CSS 框架
- **前端一律使用 Tailwind CSS**
- 響應式設計、無障礙設計 (WCAG 2.1 AA)
- 支援現代化主題（深色/淺色/玻璃效果）

### 建置工具
- **Vite**: 建置工具
- **Alpine.js**: 互動式功能
- **Axios**: HTTP 客戶端
- **ESLint + Prettier**: 程式碼格式化

## 6. 後端開發規範

### Go 後端 (Gin Framework)
- **高效能**: 利用 Gin 的 40 倍速度優勢
- **中介軟體**: 擴展日誌、授權、錯誤處理功能
- **結構化配置**: 環境變數和設定檔管理
- **微服務準備**: 輕量化架構支援未來擴展

### Laravel 前端 (PHP 8.2 + Laravel 12)
- **現代化功能**: 利用 Laravel 12 的最新特性
- **安全性**: CSRF 保護、輸入驗證、JWT 認證
- **效能優化**: 快取策略、資料庫優化、預載入
- **測試框架**: PHPUnit 或 Pest

## 7. 資料庫開發規範

### PostgreSQL 最佳實踐
- **版本**: PostgreSQL 16 (支援最新功能)
- **查詢優化**: 使用 EXPLAIN 分析效能瓶頸
- **索引策略**: 適當索引和資料庫架構設計
- **備份策略**: 定期完整和增量備份

### 架構設計
- **正規化**: 減少冗餘，邏輯組織資料
- **效能考慮**: 讀取密集操作適度反正規化
- **監控**: 追蹤執行時間、資源使用、系統警報

## 8. Code Review 強制規範

### 完整 Code Review 流程
完成每個 Task 後必須執行：

1. **編譯與語法檢查**: Go build、npm lint、PHP artisan 檢查
2. **相依性與衝突檢查**: 驗證 import、路由、API 端點
3. **整合測試**: 測試新舊功能交互和權限控制
4. **程式碼品質審查**: 命名、重複、效能、安全性檢查
5. **文件一致性檢查**: API 文件、README、技術架構文件
6. **回歸測試**: 手動測試主要功能和相容性

### Code Review 檢查清單
- [ ] 所有新增程式碼都能正常編譯
- [ ] 沒有與現有程式碼的衝突或重複
- [ ] 所有相關測試都通過
- [ ] API 端點命名和回應格式符合規範
- [ ] 程式碼符合專案的命名和格式規範
- [ ] 有適當的錯誤處理和日誌記錄
- [ ] 安全性考量已被妥善處理

## 9. TaskMaster 記錄規範

### 雙重記錄機制
每完成任務必須同時更新：

1. **TaskMaster 系統狀態**
   ```bash
   mcp__task-master-ai__set_task_status([
       'id' => '<task-id>',
       'status' => 'done',
       'projectRoot' => '/Users/gamepig/projects/NexusERP'
   ]);
   ```

2. **Task-Update.md 詳細記錄**
   - 技術實作細節、程式碼片段
   - 問題解決過程、測試驗證
   - 檔案變更統計、效能分析

## 10. 任務執行暫停機制

### 暫停觸發條件
完成以下「主要任務」後必須暫停：
- 完整任務完成
- 關鍵子任務完成
- 重大功能里程碑
- 問題修復完成
- 架構性變更完成

### 暫停執行步驟
1. **立即暫停工作**
2. **完整記錄進度**: 更新 Task-Update.md、memory-bank、TaskMaster
3. **狀態確認與等待**: 提供摘要報告，等待使用者指示

## 11. 安全性與隱私規範

### 敏感資訊處理
- 不得在程式碼中硬編碼密碼、API 金鑰
- 所有敏感資訊必須來自 `.env`
- 前端不得將敏感資訊暴露於瀏覽器端

### 安全最佳實踐
- 防止 SQL 注入、XSS 攻擊
- 實施完整的例外處理機制
- 使用 JWT 認證和權限控制

## 12. 開發環境配置

### 系統要求
- **開發環境**: macOS 15
- **容器化**: Docker Compose 部署
- **端口管理**: 嚴格遵循固定端口配置，禁止修改

### 工具鏈
- **Go**: 1.23 (後端 API)
- **PHP**: 8.2 + Laravel 12 (前端 Web)
- **Node.js**: Vite + TailwindCSS (建置工具)
- **PostgreSQL**: 16 (主資料庫)
- **Redis**: 7 (快取系統)
