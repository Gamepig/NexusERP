# 通用任務完成要求

## 🚨 **強制性規則：E2E 測試驗證**

### **適用於所有任務類型**
無論任務大小、複雜度或類型，**所有任務**在標記為 "done" 前都必須通過 Playwright E2E 測試驗證。

### **核心原則**
1. **實際操作優於理論驗證**
2. **用戶體驗優於技術實現**
3. **端到端測試優於單元測試**
4. **真實環境優於開發環境**

### **測試範圍要求**
- **功能完整性**：所有新增/修改的功能
- **用戶流程**：完整的用戶操作路徑
- **錯誤處理**：異常情況的正確處理
- **數據一致性**：前後端數據同步驗證
- **權限控制**：認證和授權機制
- **響應性**：UI 響應和性能表現

### **測試執行標準**
1. **測試腳本位置**：`documents/test_scripts/`
2. **測試環境**：真實部署環境（非 mock）
3. **測試瀏覽器**：實際瀏覽器環境
4. **測試數據**：使用真實或類真實數據
5. **測試記錄**：詳細記錄測試過程和結果

### **違反規則的處理**
- 任務狀態**不得**標記為 "done"
- 必須補充完整的 E2E 測試
- 重新評估任務完成標準
- 記錄未完成原因和後續計劃

### **質量保證流程**
1. **開發完成** → 2. **自我測試** → 3. **E2E 驗證** → 4. **問題修復** → 5. **重新測試** → 6. **標記完成**

### **測試文檔要求**
- 測試執行時間和環境
- 測試腳本路徑和版本
- 測試結果截圖或錄影
- 發現問題的詳細記錄
- 修復措施和驗證結果
- 最終確認聲明

這個規則確保每個任務的交付品質達到生產環境標準，避免「看似完成但實際無法使用」的情況。
