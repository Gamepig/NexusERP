## 1. 專案概觀

*(本節內容主要來自 `memory-bank/projectbrief.md`)*

### 1.1. 專案名稱
NexusERP

### 1.2. 專案目標
開發一個模組化的、整合 AI 功能的 ERP Web 應用程式，旨在提高中小企業（特別是跨行業經營者）的營運效率、決策品質和供應鏈管理能力。

### 1.3. 核心挑戰與機會
*   **挑戰:** 滿足多樣化的行業需求（15 個目標行業），整合複雜的 AI 功能（預測、推薦、影像辨識、自然語言處理），確保系統穩定性、安全性與易用性。
*   **機會:** 利用 AI 自動化重複任務，提供智慧洞察與預警，建立 Marketplace 促進供應商與買家連結，為傳統 ERP 市場帶來創新。

### 1.4. 專案範圍
開發一個 Web 應用程式，包含 10 個核心功能模組，整合多項 AI 能力，支援 15 個目標行業（按優先級開發），並提供 Docker 化部署方案。

### 1.5. 主要利害關係人
*   開發團隊
*   目標使用者（中小企業主、營運管理者）
*   (未來) Marketplace 參與者（買家、供應商）

### 1.6. 限制與假設
*   開發時間與資源有限，需遵循開發順序。
*   外部 AI 服務 (OCR, RAG/CAG) 的可用性與成本。
*   使用者願意採用 AI 功能並提供數據。
*   網路連線穩定性（影響雲端功能與外部 API）。
*   部分規劃文件缺失（如 App 功能清單、資料庫表結構），需在開發過程中補足。

## 2. 產品情境

*(本節內容主要來自 `memory-bank/productContext.md`)*

### 2.1. 目標使用者
*   **主要:** 中小型企業 (SMBs)，特別是那些需要跨不同行業別管理業務的經營者（例如，同時經營養雞場和零售雞肉攤）。
*   **次要:** Marketplace 上的買家和供應商（在 Marketplace 模組上線後）。

### 2.2. 使用者痛點
*   傳統 ERP 系統昂貴、複雜且缺乏彈性。
*   資訊孤島導致數據整合分析困難。
*   重複性人工任務耗時。
*   缺乏數據洞察力，難以預測和優化。
*   尋找可靠供應商耗時費力。
*   法規遵循資訊獲取困難。

### 2.3. NexusERP 解決方案
*   提供模組化、彈性、易用的 Web ERP 系統。
*   利用 AI 實現自動化（OCR）、智慧洞察（預測、推薦、報表解釋）與便捷互動（助手、語音）。
*   支援跨行業業務單位整合管理。
*   建立 Marketplace 連接供應商與買家，AI 驅動高效採購。
*   整合 AI 知識庫與法規資訊輔助工具。

### 2.4. 核心價值主張
*   **提升效率:** 自動化流程。
*   **智慧決策:** AI 驅動的洞察。
*   **降低成本:** 優化庫存與採購。
*   **增強連結:** Marketplace 生態系。
*   **簡化管理:** 統一平台管理跨行業業務。
*   **易於使用:** 現代化介面與 AI 輔助。

### 2.5. 產品定位
一款專為中小企業及跨行業經營者設計的、具備強大 AI 功能和 Marketplace 生態系的現代化 ERP 解決方案。

### 2.6. 市場機會
*   填補中小企業及跨行業 ERP 市場空白。
*   AI 技術提供差異化競爭優勢。
*   Marketplace 建立網絡效應。

### 2.7. 主要競爭對手 (潛在)
*   傳統 ERP 供應商 (SAP Business One, Oracle NetSuite)。
*   雲端會計軟體 (QuickBooks, Xero)。
*   行業特定軟體。
*   新興 AI 驅動的業務管理平台。

## 3. 功能需求

*(本節內容主要來自 `memory-bank/projectbrief.md`, `documents/AI規劃.md`, `documents/規劃1.md`, `documents/規劃2.md`, `documents/跨行業業務場景.md`)*

### 3.1. 核心功能模組
1.  庫存管理
2.  銷售管理
3.  財務管理
4.  人力資源管理 (Phase 3)
5.  智慧預警與預測
6.  儀表板與報表洞察
7.  影像辨識管理 (OCR)
8.  會計系統整合
9.  AI 法規資訊輔助
10. Marketplace (供應商推薦與交易平台)

### 3.2. 核心 AI 能力
*   **預測與推薦:** 供應商推薦、銷售/需求預測、庫存預測與預警、促銷建議、內部供應鏈調度、成本/價格預測與定價建議、預測性維護。
*   **自動化與優化:** 業務流程自動化、內部轉移自動化、採購時機判斷、AI 引導會計設定、自然語言填單。
*   **資料處理與分析:** AI 影像辨識 (OCR+NLP)、自訂報表生成、跨單位報表分析、報表自然語言解釋。
*   **使用者互動:**
    *   **目標導向問答 (整合於 AI 助手):** 允許使用者提出具體的營運問題 (如 "雞隻健康狀況"、"生產線效率"、"農藥使用時機")。AI 負責引導釐清問題細節，並利用內部知識庫 (RAG/CAG) 或外部網路資源尋找答案。**為控制成本，此功能將避免閒聊，專注於問題解決。** 技術上考慮採用兩階段模型：主模型判斷意圖，若為提問則交由小型專用模型處理。
    *   AI 引導式註冊/資料完善
    *   AI 助手 (查詢/操作/導航/語音，**整合目標導向問答**)
    *   AI 知識庫 (RAG/CAG，**支援目標導向問答**)
    *   AI 法規資訊輔助
    *   自然語言填單

### 3.3. 重點功能詳述

#### 3.3.1. Marketplace (供應商推薦與交易平台)
*   **定位:** 獨立模組，會員間的供應商交易與交流平台。
*   **功能:**
    *   會員資料與 ERP 內部資料（庫存、財務、銷售）同步。
    *   會員間交流（訊息系統、評價與反饋、討論區）。
    *   AI 供應商推薦（多維度分析：成本、價格、評價、運輸時間、歷史表現、庫存需求，結合內外部數據）。
    *   自動進貨單生成（AI 判斷採購時機，生成草稿，使用者確認後下單）。
    *   交易管理（訂單生成、追蹤、付款，整合影像辨識與會計）。
    *   供應商評價與反饋系統。
    *   外部整合（B2B 平台 API、物流 API）。
*   **電商強化:** 針對電商需求優化（快速交貨推薦、多通路庫存同步、競爭對手價格分析、促銷建議）。

#### 3.3.2. AI 影像辨識 (OCR)
*   **支援文件:** 發票、合約、菜單、銷售記錄、名片、進貨單、出貨單、報價單、收據、使用者自訂文件。
*   **流程:** AI 文件分類 → OCR 提取文字 → NLP 理解語義與結構化 → 資料寫入對應模組。
*   **能力:** 支援中文、多語言、手寫、模糊文件，提供校驗機制。
*   **應用:** 自動更新財務（發票）、庫存（進貨單）、客戶資料（名片），Marketplace 供應商資訊提取。

#### 3.3.3. AI 互動相關功能 (原 AI 知識庫及助手相關內容整合)

*   **AI 助手:**
    *   **介面:** 整合於現有懸浮按鈕/聊天窗口。
    *   **核心能力:**
        *   系統查詢 (如 "查詢庫存")
        *   系統操作 (如 "建立訂單")
        *   頁面導航
        *   語音輸入/輸出
        *   **目標導向問答 (詳見 3.2):** 處理特定營運問題。

*   **AI 知識庫 (RAG/CAG):**
    *   **技術:** 整合 MCP SERVER TOOLS、RAG (檢索增強生成)、CAG (上下文感知生成)。
    *   **內容:** 行業實務、供應商資料 (與 Marketplace 共享)、操作手冊、FAQ、**(新增) 過往問答記錄 (若適用)**。
    *   **應用:**
        *   **支援目標導向問答：** 為問答功能提供核心資訊來源。
        *   回答使用者關於系統操作、行業知識等的提問。
        *   動態生成操作建議。
        *   提供供應商風險分析 (輔助 Marketplace)。

#### 3.3.4. 智慧預警與預測
*   **預警:** 基於內部數據（庫存水位、帳款）和外部數據（天氣、新聞、市場價格 via MCP TOOLS）觸發。
*   **預測:** 銷售預測、需求預測、庫存預測、成本/價格預測。
*   **模型:** 整合時間序列模型 (ARIMA, Prophet) 或更複雜模型 (LSTM)，結合外部因素。
*   **應用:** 優化庫存、預防風險、輔助採購與定價決策。

#### 3.3.5. 會計系統整合
*   **支援:** QuickBooks, Xero, SAP (及其他潛在系統)。
*   **功能:** 雙向同步（客戶、供應商、發票、付款），支援 API 或檔案匯入/匯出。
*   **AI 引導:** AI 根據使用者選擇的軟體或口述習慣，引導完成設定與欄位映射。

#### 3.3.6. 跨行業支援
*   **核心:** 單一企業可建立多個「業務單位」(Business Units)。
*   **標籤:** 每個業務單位可標記不同行業（如 農業、零售業）。
*   **數據隔離:** 透過 `business_unit_id` 和應用層邏輯或 RLS 實現數據區隔。
*   **流程整合:** 支援跨業務單位的操作（如內部庫存轉移）。
*   **AI 適應:** AI 根據業務單位的行業標籤，提供相關的預測、推薦與功能。

## 4. 技術規格

*(本節內容主要來自 `memory-bank/systemPatterns.md`, `memory-bank/techContext.md`, `documents/nexus-erp-docker-deployment-guide-macos.md`, `NexusERP-rules.mdc`)*

### 4.1. 系統架構
*   **總體:** 模組化架構，前後端分離。
*   **前端:** PHP/Laravel (Blade 模板)，Vite 打包。
*   **後端:** Golang/Gin (RESTful API)。
*   **Marketplace:** 考慮微服務架構，使用 WebSocket/消息隊列 (RabbitMQ) 處理即時通訊。
*   **非同步處理:** 使用 Redis + Worker 或 Goroutines 處理耗時任務。

### 4.2. 技術堆疊
*   **語言:** Go (後端), PHP (前端), JavaScript (前端互動)
*   **框架:** Gin (Go), Laravel (PHP)
*   **資料庫:** PostgreSQL, Redis
*   **前端庫:** Chart.js, Web Speech API
*   **容器化:** Docker, Docker Compose
*   **檔案儲存:** S3 或相容服務 (MinIO)
*   **其他:** Nginx, Supervisor (容器內)

### 4.3. 數據管理
*   **主庫:** PostgreSQL。
*   **隔離:** 透過 `business_unit_id` + 應用層邏輯 (推薦) 或 RLS。
*   **半結構化:** 使用 JSONB。
*   **快取:** Redis。
*   **遷移:** GORM Migrations 或類似工具。
*   **ORM:** GORM (Go)。

### 4.4. AI/ML 整合模式
*   **混合策略:** 優先外部成熟服務 (OCR, RAG/CAG, MCP TOOLS, LLM)，核心預測/推薦考慮內部模型。
*   **非同步處理:** 任務佇列處理耗時 AI 任務。

### 4.5. 安全性
*   **認證:** 後端 (Go) bcrypt + JWT/Session，前端 (Laravel) 管理 Session。
*   **授權:** RBAC。
*   **傳輸:** 全站 HTTPS。
*   **數據:** 靜態加密，避免日誌記錄敏感資訊。
*   **防護:** OWASP Top 10 (輸入驗證等)。
*   **API 安全:** 速率限制、認證、授權。
*   **金鑰管理:** 環境變數或 Secret Management。
*   **Marketplace:** 交易加密、身份驗證、防詐欺。

### 4.6. API 設計原則
*   RESTful 風格。
*   JSON 格式。
*   OpenAPI/Swagger 文件。
*   版本化。
*   標準 HTTP 狀態碼。
*   一致的錯誤處理。

### 4.7. 外部服務依賴
*   MCP SERVER TOOLS API
*   OCR 服務 API
*   RAG/CAG 模型 API
*   LLM API (如 OpenRouter)
*   會計系統 API (QuickBooks, Xero)
*   支付閘道 API (Stripe, PayPal)
*   物流追蹤 API (FedEx, DHL)
*   電商平台 API (Shopify, Amazon)
*   B2B 平台 API / 公開供應商資料庫

### 4.8. 環境變數
*   參考 `NexusERP-rules.mdc` 範本，配置 Session Secret, OAuth Keys, URLs/Ports, **PostgreSQL** 連線資訊, 外部 API 金鑰, AI 模型配置, Laravel APP_KEY。

## 5. 開發計畫

*(本節內容主要來自 `documents/Task.md`, `documents/開發順序.md`, `NexusERP-rules.mdc`)*

### 5.1. 開發流程與原則
*   **流程:** 敏捷開發，分階段交付。
*   **版本控制:** Git，遵循 Gitflow 或類似分支策略。
*   **程式碼品質:** 遵循 `NexusERP-rules.mdc` 中的效能優先、簡潔、格式規範、最小代碼量、防禦性程式設計原則。
*   **修改原則:** 優先修改現有程式碼，避免重寫，同步更新文件，嚴禁擅自修改/新增功能。
*   **重複控制:** DRY 原則，建立共用模組。
*   **註解:** 關鍵業務邏輯、複雜演算法、API 接口需有中文註解。
*   **術語:** 使用台灣用語 (參考 `CS_TW_CN_TERMS*.md`)。

### 5.4. 測試策略
*   **單元測試:** 後端 (Go `testing`, `testify`)、前端 (PHPUnit)。專注邏輯。
*   **整合測試:** 測試模組間互動、API 串接。
*   **端對端測試 (E2E):** 模擬使用者真實操作流程。
*   **使用者驗收測試 (UAT):** 由目標使用者進行測試。
*   **AI 功能評估:** 預測準確度 (MAPE, RMSE)、推薦效果 (CTR)、OCR 準確率。
*   **最小必要原則:** 避免引入不必要的測試依賴。

## 6. 部署策略

*(本節內容主要來自 `documents/nexus-erp-docker-deployment-guide-macos.md`, `memory-bank/systemPatterns.md`, `Task.md`)*

### 6.1. 容器化
使用 Docker 將所有服務（前端 Laravel/Nginx, 後端 Go, PostgreSQL, Redis）容器化。

### 6.2. 本地/開發環境
使用 Docker Compose 編排容器，提供一致的開發與測試環境 (參考 `nexus-erp-docker-deployment-guide-macos.md`)。考慮使用 Supervisor 管理容器內多進程。

### 6.3. 雲端部署 (規劃)
*   目標平台: Kubernetes (EKS/GKE), AWS ECS, 或 Serverless (AWS App Runner)。
*   映像倉庫: Docker Hub, AWS ECR。
*   基礎設施: VPC, Subnets, Security Groups, Load Balancers。
*   儲存: S3 for files, Managed PostgreSQL/Redis。
*   監控/日誌: 雲端原生服務或 Datadog, ELK/Loki。

### 6.4. CI/CD
考慮使用 GitHub Actions 或類似工具，自動化建置、測試（單元/整合）及部署到測試/生產環境。

## 7. 風險管理

*(綜合各文件)*

*   **技術風險:**
    *   AI 模型效果不佳 (預測不準、推薦不相關): 持續評估、迭代模型、調整權重。
    *   外部 API 變更/不穩定/成本增加: 設計容錯機制、尋找替代方案、監控成本。
    *   整合複雜度高 (多系統、多 API): 充分測試、標準化接口。
*   **專案風險:**
    *   範圍蔓延: 嚴格遵循開發計畫與優先級。
    *   開發延遲: 採用敏捷開發、及早識別瓶頸。
    *   資源不足: 根據開發階段合理規劃資源。
*   **產品風險:**
    *   使用者接受度低 (尤其 AI 功能): 加強 UX 設計、提供引導與說明、收集反饋。
    *   Marketplace 交易糾紛: 建立清晰規則、評價機制、爭議處理流程。
    *   數據安全/隱私問題: 嚴格遵循安全規範、加密、權限控制、法規遵循 (GDPR, HIPAA)。
*   **外部風險:**
    *   法規變更: 利用 AI 法規輔助工具監控、及時調整。
    *   市場競爭加劇: 持續創新、強化核心優勢。
