# NexusERP 綜合開發修復計畫

## 📋 執行摘要

基於 2025-07-29 詳細實際測試分析，本計畫解決了系統核心問題並優化使用者體驗。

### 🎯 主要發現

1. **報表系統**: 8/9 報表正常運作，1個報表（採購商品分析）需修復
2. **RLS 多租戶隔離**: 資料庫架構完整，但 Laravel 中間件配置問題
3. **表單編輯功能**: 基本結構正確，關聯資料載入受 RLS 配置影響
4. **核心問題**: Laravel 中間件未正確設置 PostgreSQL 上下文

---

## 🔥 關鍵問題分析

### 問題 1: Laravel 中間件上下文設置失效
**影響**: 所有 RLS 功能、表單資料載入、搜尋功能
**根本原因**: `app.current_company_id` 未正確設置，導致所有 RLS 政策失效
**證據**: 
- 測試結果顯示 `current_company_id = not set`
- 客戶、產品、供應商的 RLS 查詢返回全部資料而非公司隔離資料

### 問題 2: 採購商品分析報表渲染失敗
**影響**: 報表系統完整性
**根本原因**: Chart.js 初始化問題或資料載入失敗
**證據**: 測試發現該頁面無 Canvas 元素，顯示「圖表載入中」

### 問題 3: 表單關聯資料載入失敗
**影響**: 編輯表單使用者體驗
**根本原因**: RLS 政策阻止跨公司關聯資料查詢
**證據**: 銷售訂單無法載入客戶資訊，採購訂單無法載入供應商資訊

---

## 🎯 開發修復計畫

### 階段一: 緊急修復 (優先級: 🔴 極高)

#### 1.1 修復 Laravel 中間件 PostgreSQL 上下文設置
**重要性**: ⭐⭐⭐⭐⭐ (系統核心功能)
**預估時間**: 4-6 小時
**負責範圍**: Laravel 中間件、PostgreSQL 連接

**詳細步驟**:
1. **檢查現有中間件**
   ```bash
   # 檢查 Laravel 中間件設置
   find app/Http/Middleware/ -name "*Company*" -o -name "*Tenant*"
   ```

2. **修復或創建公司上下文中間件**
   ```php
   // app/Http/Middleware/SetCompanyContext.php
   public function handle($request, Closure $next)
   {
       if (auth()->check()) {
           $companyId = auth()->user()->currentCompany->id;
           DB::statement("SELECT set_config('app.current_company_id', ?, false)", [$companyId]);
           DB::statement("SELECT set_config('app.current_user_id', ?, false)", [auth()->id()]);
       }
       return $next($request);
   }
   ```

3. **驗證中間件註冊**
   - 檢查 `app/Http/Kernel.php` 中間件註冊
   - 確保在需要的路由群組中啟用

4. **測試驗證**
   ```bash
   php test-rls-management-pages.php
   ```

**成功標準**:
- RLS 測試通過率達到 7/7
- 所有管理頁面正確顯示公司隔離資料
- 搜尋功能只返回當前公司資料
