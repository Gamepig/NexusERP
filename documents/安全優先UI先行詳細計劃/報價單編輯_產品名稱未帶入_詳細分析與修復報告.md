## 編輯報價單頁面：產品名稱未帶入 - 詳細分析與修復報告

### 摘要
- **症狀**: 進入編輯頁 `/quotes/{id}/edit`（與多步驟 `/quotes/{id}/edit/multi-step`）時，報價項目列的「產品/服務」欄位為空白，未顯示原先建立時的產品名稱。
- **根因（關鍵）**:
  1) 編輯頁使用的資料未做標準化；`QuoteController@edit` 直接把 Go API 回傳資料丟到 View，沒有像顯示頁那樣調用 `normalizeQuoteData()` 將缺失名稱補齊。
  2) Go API 回傳的 items 內，產品名稱存在於巢狀欄位 `item.product.name`，而前端表單 View 讀取的是 `item['name']` 或 `item['product_name']`，導致顯示空白。
  3) Go Service 在載入 items 時雖有附帶 `product` 物件，但未提供扁平化欄位供現有 View 直接取用；另外 `getQuoteItems` 採逐筆查詢，存在 N+1 性能風險。

### 2. 根因拆解
- 編輯頁未標準化 → 沒有把 `product.name` 映射到 `item['name']`/`item['product_name']`。
- View 僅讀扁平欄位 → 即使 API 已附 `item.product.name`，也不會顯示。
- 後端回傳結構與前端表單期望不一致 → 顯示落空。

---

### 3. 修復方案（由易到難）

#### A. 最小前端修復（立即見效）
- 在 `quotes/form.blade.php` 與多步驟表單讀值時加入巢狀備援：

```diff
// frontend/resources/views/quotes/form.blade.php
- value="{{ $item['name'] ?? $item['product_name'] ?? '' }}"
* value="{{ $item['name'] ?? ($item['product']['name'] ?? ($item['product_name'] ?? '')) }}"
```

#### B. 控制器一致化（顯示/編輯都標準化）
- 在 `QuoteController@edit` 與 `editMultiStep` 取得 quote 後，呼叫 `normalizeQuoteData($quote)` 再丟入 View：

```diff
// frontend/app/Http/Controllers/Web/QuoteController.php
 $quote = $quoteResponse->json()['quote'];
+$quote = $this->normalizeQuoteData($quote);
 return view('quotes.form', [..., 'quote' => $quote, ...]);
```

優點：不需動 View；同時修正日期欄位映射等一致性問題。缺點：每個 item 可能各打一支產品查詢（可之後優化批次）。

#### C. 後端回傳扁平欄位（中期）
- 在 Go 端的 `enrichQuoteWithDetails` 或 `getQuoteItems` 完成後，序列化前將 `item.Product.Name` 映射為額外欄位，例如 `product_name`（需擴充輸出模型，或在前端改讀 `product.name`）。
- 或統一前端改讀巢狀 `product.name`，同時清理舊的 `name/product_name` 依賴（需全站盤點）。

#### D. 效能優化（可選）
- 參考 `CreateQuote` 之批次載入作法，將 `getQuoteItems` 的逐筆 `getProductByID` 改為一次 `IN (...)` 查詢後 map 回各項目，避免 N+1。

---

### 4. 驗證計畫
- 單元/整合：
  - 編輯頁渲染：含有 `item['name']` 或 `item['product']['name']` 時正確顯示。
  - 顯示與編輯頁採用相同標準化路徑，產品名稱一致。
- E2E（Playwright）：
  - 進入 `/quotes/{id}/edit`，抓取第一個項目的名稱文字需非空；另外在多步驟編輯頁也驗證。

---

### 5. 建議路線
1) 先採 A（前端最小調整）+ B（控制器標準化），立即修復顯示問題且保持一致性。
2) 下一步導入 D 的批次查詢以消除 N+1；如需長期維護，考慮 C 統一前端改讀 `product.name` 並清理歷史欄位依賴。
