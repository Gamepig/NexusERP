### 三、根因彙整
- 後端模型 `CreateQuoteRequest` 缺少 `Status`；Service 在 INSERT 固定寫 `draft`。
- 前端送出的值包含 `sent`、`accepted`，與 DB/Go 的 `pending`、`approved` 不一致。
- 多步驟與單頁表單之間的狀態選項也不一致（多步驟無 `approved`）。

### 四、為何「修改後」仍有問題
- 若只在前端或 Laravel 層傳 `status`，Go 仍忽略（因為沒有欄位、且 Service 硬寫 `draft`）。
- 若後端尚未加入 `Status` 接受與合法化映射，最終仍會寫入 `draft`。

### 五、修復方案（權威與最小改動兩路並行）

#### A. 權威修復（建議）
1) Go 模型加入 `Status` 欄位

```diff
// backend/internal/models/quote.go
 type CreateQuoteRequest struct {
   CustomerID int64 `json:"customer_id" binding:"required"`
   ...
+  Status     *string `json:"status,omitempty"`
   Items      []CreateQuoteItemRequest `json:"items" binding:"required,min=1"`
 }
```

2) Go Service 合法化與映射，INSERT 使用之

```diff
// backend/internal/services/quote_service.go
// 1) 先決定要寫入的狀態
 statusToUse := models.QuoteStatusDraft
 if req.Status != nil {
   switch *req.Status {
   case models.QuoteStatusDraft, models.QuoteStatusPending, models.QuoteStatusApproved, models.QuoteStatusRejected, models.QuoteStatusExpired:
     statusToUse = *req.Status
   case "sent":     statusToUse = models.QuoteStatusPending
   case "accepted": statusToUse = models.QuoteStatusApproved
   }
 }
// 2) INSERT 改用 statusToUse
- err = tx.QueryRowx(query, ..., models.QuoteStatusDraft).StructScan(quote)
+ err = tx.QueryRowx(query, ..., statusToUse).StructScan(quote)
```

3)（可選）Handler 層再做一次白名單驗證，回傳 400 對於非法狀態。

#### B. 最小改動（若暫時不能動 Go）
1) Laravel 在送往 Go 前做值映射：

```diff
// frontend/app/Http/Controllers/Web/QuoteController.php
 $status = $validated['status'] ?? 'draft';
 $map = ['sent' => 'pending', 'accepted' => 'approved'];
 $quoteData['status'] = $map[$status] ?? $status; // 讓 Go 未改時也能寫入正確列舉
```

2) Blade 選單 value 統一：
   - 使用 `draft|pending|approved|rejected|expired`（顯示文字仍可「已發送/已接受」）。

```diff
// form.blade.php 與 multi-step-form.blade.php
- <option value="sent">已發送</option>
+ <option value="pending">已發送</option>
- <option value="accepted">已接受</option>
+ <option value="approved">已接受</option>
```

### 六、驗證計畫
- Go 單元：`CreateQuote(status=pending/approved/rejected/expired)` 均正確；`sent/accepted` 映射後正確；未給則為 `draft`。
- E2E：
  - 單頁與多步驟表單各選一次「已發送」→ DB 應為 `pending`。
  - 選「已接受」→ DB 應為 `approved`。
  - 未選狀態 → `draft`。

### 七、結論
- 目前根因仍在後端未接受/未使用 `status`，且 Service 硬塞 `draft`。僅前端/Controller 調整仍不足。
- 建議：先做「最小改動」立即改善，隨後完成「權威修復」於 Go 層，兩者可相容不衝突。
