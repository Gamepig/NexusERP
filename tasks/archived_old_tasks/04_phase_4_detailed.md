# Phase 4: AI 整合、進階分析與平台強化 (AI Integration, Advanced Analytics & Platform Enhancement)

**核心目標：** 整合 AI 功能（RAG/CAG、智慧預測、自動化建議），實現更進階的 BI 與數據分析，強化分店管理與協同，完善財務管理（預算、成本核算），擴展供應鏈金融，並提升平台效能與安全性。

--- 

## P4.1: AI 功能整合 (AI Feature Integration)
*參考 `documents/NexusERP_AI_Features_Detailed_Planning.md` 中的詳細規劃*

### P4.1.1: AI 助理 (智能夥伴) 核心功能實現
*   **P4.1.1.1: LLM/RAG/CAG 引擎選型與基礎建設**
    *   P4.1.1.1.1: 確定並配置 OpenRouter 或其他 LLM 服務 API。
    *   P4.1.1.1.2: 搭建 RAG 框架：向量數據庫 (e.g., Pinecone, Weaviate, or pgvector for PostgreSQL) 選擇與配置。
    *   P4.1.1.1.3: 實現內部文檔 (ERP 操作手冊、產品知識庫等) 的索引與向量化，供 RAG 檢索。
*   **P4.1.1.2: 自然語言查詢 ERP 數據**
    *   P4.1.1.2.1: 後端 (Golang) 實現 NLU 模組，將自然語言查詢轉換為結構化 API 請求或 SQL 查詢 (需注意安全性，避免 SQL 注入)。
    *   P4.1.1.2.2: 整合 LLM 進行查詢意圖理解和查詢語句生成。
    *   P4.1.1.2.3: 前端提供 AI 助理聊天視窗，接收用戶查詢，調用後端處理並展示結果。
    *   P4.1.1.2.4: 實現 P2.1.1.1 (AI 助理) 中資料查詢範例的核心功能。
*   **P4.1.1.3: 自然語言執行 ERP 操作 (基礎)**
    *   P4.1.1.3.1: 識別用戶操作意圖 (如「創建採購訂單」)，並引導用戶提供必要信息。
    *   P4.1.1.3.2: 後端 API 接收操作指令和參數，調用相應的業務邏輯 API。
    *   P4.1.1.3.3: 實現 P2.1.1.1 (AI 助理) 中系統操作範例的基礎功能 (如創建草稿、發送提醒)。
*   **P4.1.1.4: 主動式提醒與建議 (基於規則和簡單預測)**
    *   P4.1.1.4.1: 後端開發定時任務或事件觸發器，監控關鍵業務指標 (如庫存水平、訂單狀態、付款逾期)。
    *   P4.1.1.4.2: 基於預設規則生成提醒和建議 (如「物料X低於安全庫存，建議採購」)。
    *   P4.1.1.4.3: AI 助理前端界面展示這些提醒。
*   **P4.1.1.5: 文件輔助與系統導航 (基礎 RAG)**
    *   P4.1.1.5.1: AI 助理能夠根據用戶提問，從已索引的內部文檔中檢索並提供相關信息 (如操作指南)。
    *   P4.1.1.5.2: 實現基礎的系統功能導航查詢 (如「如何新增客戶？」助理回答操作步驟或提供連結)。

### P4.1.2: 智慧預測模型初步應用 (基礎機器學習)
*   **P4.1.2.1: 需求預測 (基礎模型)**
    *   P4.1.2.1.1: 收集歷史銷售數據 (P2.1.3)。
    *   P4.1.2.1.2: 選擇並實現基礎時間序列預測模型 (e.g., ARIMA, Exponential Smoothing in Python/Go, or using a cloud ML service)。
    *   P4.1.2.1.3: 後端 API 提供需求預測結果。
    *   P4.1.2.1.4: 前端展示基礎的需求預測圖表。
*   **P4.1.2.2: 銷售預測 (基於機會 - P3.4.2.2 擴展)**
    *   P3.4.2.2.1: 結合更多歷史數據和客戶行為訓練更精準的機會轉化率模型。

### P4.1.3: AI 語音控制核心功能實現
*   **P4.1.3.1: NLU 引擎整合與優化 (針對語音指令)**
    *   P4.1.3.1.1: 選擇或訓練 NLU 模型以更好地理解口語化的 ERP 操作指令。
*   **P4.1.3.2: 核心業務流程的語音操作支持**
    *   P4.1.3.2.1: 實現對常用查詢 (如查庫存、查訂單狀態) 的語音支持。
    *   P4.1.3.2.2: 實現對常用數據輸入 (如創建簡單任務、記錄筆記) 的語音支持。
*   **P4.1.3.3: 與 MCP (Model Context Protocol) 整合準備 (若 MCP 方案已初步確定)**
    *   P4.1.3.3.1: 設計語音指令到 MCP 操作的轉換邏輯。

### P4.1.4: 外部數據整合 AI 應用 (天氣、新聞、網路搜尋 - 實際應用)
*   (參考 `documents/NexusERP_AI_Features_Detailed_Planning.md` 2.5 節)
*   **P4.1.4.1: 過去數據搜尋 (網路與資料庫) 功能完善**
    *   P4.1.4.1.1: AI 助理能夠調用外部搜索引擎 API (e.g., Google Search API, Bing API) 並結合內部資料庫結果，呈現綜合答案。
*   **P4.1.4.2: 天氣數據影響分析 (整合至預測模型)**
    *   P4.1.4.2.1: 將 P3.7.3.1 獲取的天氣數據作為特徵，加入需求預測模型 (P4.1.2.1)。
    *   P4.1.4.2.2: 分析天氣對物流、戶外作業的影響，並在相關模塊提供預警。
*   **P4.1.4.3: 網路新聞關聯性分析 (初步警示系統)**
    *   P4.1.4.3.1: 設定關鍵詞監控 (如供應商名稱、主要原料、行業政策)。
    *   P4.1.4.3.2: AI 初步判斷新聞事件的潛在影響 (正面/負面/中性)，並向相關人員發出預警。

## P4.2: 進階 BI 與數據分析 (Advanced BI & Data Analytics)

### P4.2.1: 數據倉庫/數據集市建設 (若 P3.7.1 決定實施)
*   **P4.2.1.1: ETL (Extract, Transform, Load) 流程開發**
    *   P4.2.1.1.1: 從 PostgreSQL 操作型數據庫抽取數據。
    *   P4.2.1.1.2: 進行數據清洗、轉換、聚合。
    *   P4.2.1.1.3: 加載到數據倉庫 (可能是另一個 PostgreSQL schema 或專用分析數據庫)。
*   **P4.2.1.2: 維度建模與事實表設計完善**
    *   P4.2.1.2.1: 實現星型/雪花型模型。

### P4.2.2: 嵌入式 BI 工具/進階圖表庫深度整合 (基於 P3.7.2 選型)
*   **P4.2.2.1: 創建更複雜的交互式儀表板**
    *   P4.2.2.1.1: 包含下鑽 (drill-down)、切片 (slice)、切塊 (dice) 功能。
    *   P4.2.2.1.2: 例如，銷售總監儀表板、採購經理儀表板、生產主管儀表板。
*   **P4.2.2.2: 用戶自定義報表功能增強**
    *   P4.2.2.2.1: 提供更友好的報表設計器界面，允許用戶拖拽維度和度量生成報表。

### P4.2.3: 預測性分析應用擴展
*   **P4.2.3.1: 客戶流失預測模型**
    *   P4.2.3.1.1: 收集客戶行為數據 (購買頻率、金額、互動記錄等)。
    *   P4.2.3.1.2: 訓練分類模型 (e.g., Logistic Regression, Random Forest) 預測流失概率。
    *   P4.2.3.1.3: 在 CRM 模塊中標示高流失風險客戶。
*   **P4.2.3.2: 供應鏈風險預測 (初步)**
    *   P4.2.3.2.1: 綜合供應商績效、外部新聞、市場波動等因素，評估供應中斷風險。
*   **P4.2.3.3: 產品推薦/交叉銷售 (Marketplace/銷售模組)**
    *   P4.2.3.3.1: 基於協同過濾或內容推薦算法，向客戶推薦相關產品。

## P4.4: 財務管理深化 (Finance Management Deepening)
*   (AP/AR/基礎GL已在 P1.6, P2.3 中建立)

### P4.4.1: 預算管理 (Budget Management)
*   **P4.4.1.1: 預算編制**
    *   P4.4.1.1.1: 資料庫模型 (`budgets` 表 - ID, budget_name, fiscal_year, department_id/business_unit_id, status (e.g., Draft, Submitted, Approved); `budget_items` 表 - budget_id, account_id, period (e.g., month), budgeted_amount)
    *   P4.4.1.1.2: 後端 API 管理預算和預算項。
    *   P4.4.1.1.3: 前端介面進行預算編制 (按部門/業務單位、會計科目、期間)。
*   **P4.4.1.2: 預算執行與控制**
    *   P4.4.1.2.1: 在費用報銷、採購申請等環節，檢查是否超出預算並提供預警/控制。
*   **P4.4.1.3: 預算差異分析報表**
    *   P4.4.1.3.1: 實際支出與預算對比分析報表。

### P4.4.2: 成本核算 (Cost Accounting - 基礎)
*   **P4.4.2.1: 產品成本核算 (標準成本法或實際成本法 - 簡化)**
    *   P4.4.2.1.1: 標準成本: 在產品主數據 (P1.1.1) 中定義標準材料成本、標準人工成本、標準製造費用。
    *   P4.4.2.1.2: 實際成本: 歸集生產訂單 (P1.3.3) 實際消耗的材料、工時、費用。
    *   P4.4.2.1.3: 計算銷貨成本 (COGS) 並在客戶發票 (P2.3.1.1) 或出貨 (P2.1.4) 時記錄相應的 GL 分錄。
*   **P4.4.2.2: 成本中心會計 (基礎)**
    *   P4.4.2.2.1: 將費用歸集到不同的成本中心 (如部門 Department P2.4.1)。
*   **P4.4.2.3: 基礎成本分析報表**
    *   P4.4.2.3.1: 產品成本分析、成本差異分析 (標準 vs 實際)。

### P4.4.3: 固定資產管理 (Fixed Asset Management - 基礎)
*   **P4.4.3.1: 固定資產主數據**
    *   P4.4.3.1.1: 資料庫模型 (`fixed_assets` 表 - ID, asset_code, asset_name, category_id, purchase_date, purchase_cost, useful_life_years, salvage_value, depreciation_method_id, current_book_value, location_id, status)
    *   P4.4.3.1.2: `fixed_asset_categories`, `depreciation_methods` 表。
*   **P4.4.3.2: 折舊計算與記錄**
    *   P4.4.3.2.1: 後端邏輯按月計算折舊。
    *   P4.4.3.2.2: 生成折舊 GL 分錄。
*   **P4.4.3.3: 固定資產報表**
    *   P4.4.3.3.1: 固定資產清單、折舊明細表。
